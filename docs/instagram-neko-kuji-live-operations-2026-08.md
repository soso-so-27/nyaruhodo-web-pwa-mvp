# Instagram 8月ねこくじ告知 ライブ運用シート

作成日: 2026-08-01
対象期間: 告知直後から翌朝まで
起点: `docs/instagram-neko-kuji-announcement-2026-08.md`
分析規範: `docs/analytics-runbook.md` / `docs/analytics-kpi-inventory.md`
障害判断: `docs/OPERATIONS-PLAYBOOK.md`

この文書は、現行の写真先行4匹ねこくじオンボを小さな波で案内したあとに、
利用者の行動、問い合わせ、未解決だけを同じ基準で確認するための一枚である。
2026-07の投稿3ライブ運用シートは当時のオンボと仮説を残す履歴であり、
8月のファネルや停止条件には使わない。

## 0. 今日の原則

1. 写真、共有範囲、4匹取得、選択結果の信頼を最優先する。
2. 入口が少ない間は率で結論を作らず、一人ずつ順序を見る。
3. 同じ操作を何度も試してもらわない。重複保存を避け、時刻と画面を先に確認する。
4. `今回は選ばない` は正常な完了であり、離脱や障害に数えない。
5. 感想を取りに行かない。自発的なDMだけを問い合わせの事実として受け取る。
6. 19:00〜21:00はP0以外のデプロイをしない。
7. 公開当日に新機能を足さない。P1以下は証跡を残し、次回告知までに一つだけ判断する。

## 2. ユーザー向け説明と内部予約を分ける

ユーザー向けオンボは次の順序で見る。

1. 自分で選ぶ写真の価値を伝える。
2. `ねこくじ` と4匹を説明する。
3. 保存前確認のあと、自分の写真を正式な `うちのこ` の1枚として保存する。
4. 4匹から気になる1匹を大きく見て、確定または「今回は選ばない」を選ぶ。
5. 1匹を確定したあとに初めて、その日の `ねこだより` と説明する。

1匹を選ぶ前の画面や告知では、次のよる8時便を約束しない。一方、内部では最初の
写真保存を起点に次回20時便を自動予約する。これは現行仕様であり、次を確認する。

- `reservation_origin=onboarding_first_photo`
- `experience_version=onboarding_choice_v1`
- 写真保存と共通の正規 `submission_id`
- 20時前の保存は当日、20時以降の保存は翌日の `delivery_date_key`
- 同じ日付に既存対象があれば上書きせず、`existing_target_preserved` として維持

ユーザー向けの見せ方から予約説明を外したことを、内部予約の廃止と解釈しない。

| タイミング | 見るもの | 判断 |
| --- | --- | --- |
| 告知直後 | bioリンク、`src=instagram_bio`、Threads自動共有なし | 入口が正しければ継続 |
| 15分後 | 入口、写真保存、4匹表示、選択、確定・選ばず完了、未解決 | 少人数は一人ずつ順序を見る |
| 60分後 | 同じファネル、次回20時便予約、端末・ブラウザ、問い合わせ | 継続・個別対応・入口停止を判断 |
| 19:00 | pending全件と当日20時便の対象 | 以後21時までP0以外デプロイ禁止 |
| 20:00〜20:15 | 予約、確認開始、成立、4匹表示、選択結果 | 開始したのに成立しない人を優先確認 |
| 21:00 | P0未解決、入口状態、問い合わせ | 事実を1行記録 |

告知時刻は中西が決める。告知後60分の確認が19:00〜21:00と重なる場合は、
日々の審査とよる8時運用を先に行い、初回確認の時刻を観測メモへ明記する。

## 4. 現行オンボで見る順序

管理画面の「写真先行オンボ」を中心に、全体ファネルと必要時の詳細イベントを補助線にする。
通常判断は写真先行ファネルで行い、保存前確認から保存までの差を調べるときだけ詳細イベントを見る。

| 段階 | イベント | 主な確認場所 | 正常な意味 |
| --- | --- | --- | --- |
| 入口 | `onboarding_intro_view` | 全体ファネル | オンボを見た |
| 価値理解 | `onboarding_kuji_intro_view` | 写真先行ファネル | 2画面目のねこくじ説明まで進んだ |
| 保存前確認 | `onboarding_photo_selected_for_review` | 必要時の詳細調査 | OS選択後、まだ正式保存していない |
| 保存確定 | `onboarding_photo_confirmed` | 必要時の詳細調査 | 保存操作を確定した |
| うちのこ保存 | `onboarding_photo_submitted` | 写真先行ファネル | 正式な1枚として保存した |
| 4匹表示 | `onboarding_preview_shown` | 写真先行ファネル | 4匹を表示した |
| 大写真確認 | `onboarding_delivery_choice_selected` | 写真先行ファネル | 気になる1匹を選んだ |
| ねこだより確定 | `onboarding_delivery_choice_saved` | 写真先行ファネル | 選んだ1匹を残した |
| 選ばず完了 | `onboarding_delivery_choice_skipped` | 写真先行ファネルの別指標 | 1匹を選ばず正常に完了した |
| 完了 | `onboarding_completed` | 全体ファネル | オンボを終えた |

`onboarding_preview_shown`、選択、確定は `candidate_count=4` を確認する。
写真選択から保存前確認へ進んだだけでは保存完了に数えない。選択と確定も別に数える。

## 5. 内部予約とよる8時便

最初の写真保存後は、次のイベントを別の運用線として見る。

| イベント | 扱い |
| --- | --- |
| `evening_delivery_reserved` | 次回20時便を新しく予約した |
| `evening_delivery_reservation_skipped` | 既存対象維持または補完期限の事情。理由を確認する |
| `evening_delivery_reservation_failed` | 実予約の不成立を確認する要確認 |
| `evening_delivery_target_repaired` | 再訪時に欠けていた軽量予約を修復した |
| `evening_delivery_check_started` | よる8時便の確認を開始した |
| `evening_delivery_check_succeeded` | 4匹の準備と保存が成立した |
| `evening_delivery_check_failed` / `timeout` | 再試行後も成立しないか確認する |
| `evening_delivery_choices_shown` | よる8時便の4匹を表示した |
| `evening_delivery_choice_saved` / `skipped` | 1匹を残した、または選ばず正常に完了した |

写真保存人数と `reserved` だけを単純比較しない。既存対象維持は正常である。
`reserved`、正常な `reservation_skipped`、修復済みを合わせても対象がない人だけを確認する。
予約済みでも20時以降にアプリを開かなければ `check_started` は発生しないため、未再訪を障害に数えない。

## 6. 止まった場所の読み方

| 止まった場所 | 第一解釈 | 扱い |
| --- | --- | --- |
| 入口から2画面目へ進まない | 興味、タイミング、説明の差 | 観測のみ |
| 写真選択を開かない | 手元の写真、安心、タイミングの差 | 観測のみ |
| 保存前確認で戻る | 写真の選び直し | 観測のみ |
| 保存操作後も `photo_submitted` がない | 読込・保存の問題 | 1人目で確認、同型2人でP0 |
| 写真保存後に4匹が出ない | 中核体験の不成立 | 再試行でも回復しなければP0 |
| 4匹を見て選ばない | 選ばないことも正常 | `skipped` なら障害ではない |
| 選んだ1匹が残らない、別の1匹が残る | 選択結果の不一致 | 1件でP0 |
| 次回20時便の対象が作られない | 内部予約の不成立 | 実データ確認後P0 |
| 既存の対象が最初の写真で上書きされた | 予約整合性の不成立 | 1件でP0 |
| 予約後に20時の確認を始めない | 未再訪 | 障害ではない |
| 20時の確認開始後も成立しない | よる8時便の不成立 | 再試行後も失敗ならP0 |

イベントは端末側キューから遅れて届くことがある。人数差だけでP0と断定せず、
本人の画面、管理画面の実データ、後続の回復イベントのいずれかを確認する。

## 7. 緊急度と初動

### P0: 入口を止める

次のどれかを確認した場合は入口を止める。

- 別人の写真、名前、場所など見えてはいけない情報が見えた
- 共有範囲と異なる写真が4匹候補や別利用者へ出た疑いがある
- 「保存して、ねこくじへ」の前に正式保存・同期・枚数加算が起きた
- 保存確定後に自分の写真が残らない、二重になる、別の写真へ替わる
- 写真保存後に4匹を取得できず、再試行でも回復しない
- 選んだ1匹が残らない、または選んでいない1匹が残る
- 次回20時便の対象が作られない、または既存対象が上書きされた
- よる8時便の確認開始後、再試行しても成立しない
- 同じ写真読込・保存停止が別の2人に起きた
- 白画面、戻れない画面、操作不能から復帰できない

初動は順番を変えない。

1. 時刻、端末、開いた場所、止まった画面を記録する。
2. 同じ写真の再投入や同じ確定操作を繰り返してもらわない。
3. bioリンクを外す。投稿自体は削除しない。
4. 写真・審査事故なら新規承認を止める。
5. 影響範囲を読み取り専用で確認する。
6. DB更新、削除、ロールバックは `PROD-OPERATIONS` と承認手順に従う。
7. `docs/incident-log/2026-08.md` へ個人情報を含めず1行記録する。

### P1: 入口を維持して個別対応

- 1人だけの復帰可能な写真読込エラー
- PWA追加案内だけが出ない、または分かりにくい
- 4匹の横幅、文字、余白などの軽い表示不良
- 再読み込みで回復し、保存結果の重複や消失がない
- 説明やボタンの意味が分かりにくい

同日中に証跡を残し、19:00〜21:00には修正しない。

### P2: 次回の判断へ送る

- 好みの差、文言、演出の磨き
- 追加機能の要望
- 一人だけの改善案

受け取ったことだけを返し、実装や時期を約束しない。

## 8. 問い合わせ確認

### 返信の目安

- P0疑い: 気づいてから15分以内に受領だけ返す
- はじめられない: 当日2時間以内
- 一般質問・感想: まとめて、遅くとも翌日
- いつでも即時返信する運用は約束しない

不具合確認で聞くのは次の4点だけにする。

1. iPhone / Android
2. Instagram / LINE / Safari / Chrome / ホーム画面アプリ
3. 止まった画面
4. おおよその時刻

可能なら画面のスクリーンショットをお願いする。写真そのもの、カード情報、写真URL、
Storageパス、認証情報は送らないよう伝える。DM原文、名前、猫の名前は運用ログへ転載しない。

### はじめられた

> 使ってくださってありがとうございます。
> 自分で選んだ写真は「うちのこ」に残り、選んだ1匹はその日の「ねこだより」から見られます。
> また気が向いた日に、ねがおを1枚のこしてみてください。

感想や再利用を追加で求めない。

### 写真を選べない、保存前確認から進まない

> お手数をおかけしてすみません。何度も選び直さなくて大丈夫です。
> iPhoneかAndroidか、どの画面から開いたかと、止まった画面・おおよその時刻を教えてください。
> エラーが見えていれば、スクリーンショットもお願いします。こちらで確認します。

### 写真を保存したが4匹が出ない

> ご連絡ありがとうございます。写真はもう一度入れず、そのままで大丈夫です。
> いま見えている画面と、開いた場所、おおよその時刻を教えてください。こちらで確認します。

### 選んだ1匹が残らない、別の1匹が見える

> ご連絡ありがとうございます。追加の操作はせず、そのままで大丈夫です。
> 画面全体のスクリーンショットと、おおよその時刻を教えてください。表示と保存の状態を確認します。

別人の情報が見えた疑いがあれば、返信と同時にP0へ上げる。

### よる8時を過ぎても4匹がとどかない

> 待っていてくださったのに、すみません。準備の状態を確認します。
> 写真は入れ直さず、いま見えている画面と、おおよその時刻を教えてください。

保存時刻と対象日を内部で確認し、未再訪、予約不成立、確認失敗を分ける。

### ホーム画面へ追加できない

> ブラウザのままでも使えます。
> iPhoneはSafariの共有ボタンから「ホーム画面に追加」、AndroidはChromeのメニューから
> 「アプリをインストール」または「ホーム画面に追加」を選べます。
> InstagramやLINEの中では出ないことがあるので、その場合はSafariかChromeで開いてください。

### 写真の扱いを聞かれた

> 選んだ写真がSNSへ自動で出ることはありません。
> 写真は、ねてるねこの中で選んだ範囲に従って保存されます。

### 改善案をもらった

> 教えてくださってありがとうございます。いまの使い心地として、受け取りました。
> すぐに変える約束はせず、使われ方を見ながら考えていきます。

公開コメントでは詳しい不具合情報を聞かず、DMへ移す。人数、反応数、残り枠を返信で語らない。

## 10. 全体への案内

個別DMで足りる間は全体へ出さない。複数人に影響し、入口を閉じた場合だけ
ストーリーズで短く案内する。

### 入口を一時停止

> いま、入口をいったん閉じて確認しています。
> すでにはじめている方で困ったことがあれば、このDMへ教えてください。

### 入口を再開

> 確認ができたので、入口を戻しました。
> 待っていてくださって、ありがとうございました。

よる8時便全体の遅れは `docs/OPERATIONS-PLAYBOOK.md` 場面3へ移る。

## 11. 翌朝のクローズ条件

次を満たせば、次の小波を続けられる。

- 保存前確認より前に正式保存された例がない
- 写真保存後の4匹取得に、未回復の欠落がない
- 選んだ1匹だけが残り、選ばず完了も正常に成立している
- 内部の次回20時便予約または既存対象維持に未解決がない
- プライバシー、共有範囲、重複、別人表示の事故がない
- よる8時の確認を始めた人は、再試行後に全員成立している
- P0未解決がない
- 問い合わせを型だけで記録し、個人情報を残していない

入口が少ないこと、4匹を見て今回は選ばないこと、よる8時に再訪しないこと、
PWAへ追加しないことは、単独では失敗にしない。
