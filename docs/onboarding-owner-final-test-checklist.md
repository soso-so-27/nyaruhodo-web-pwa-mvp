# オンボーディング 最終実機チェックリスト

更新日: 2026-08-01
対象: 現行ねこくじオンボの告知前に、オーナーが実機で確認する最小関門と回帰確認

## 0. 準備

- 本番入口: `https://neteruneko.jp/onboarding?src=instagram_bio`
- テスト用reset入口: `https://neteruneko.jp/onboarding?src=instagram_bio&reset_onboarding=1`
- reset入口は、その端末・そのドメインのオンボ用ローカル状態だけを消す。サーバ上のアカウントや写真は削除しない。
- PWA追加案内はシークレットタブで制限される場合がある。案内確認だけは通常タブで行う。
- 問題が出たら、端末、OS、開いたブラウザ、時刻、画面を記録する。

## 1. 8月告知の公開関門

告知当日はA〜Cを行う。深い回帰は§2へ分け、毎回の公開判断を重くしすぎない。

### A. Instagram内ブラウザ

1. Instagramアプリ内で本番入口を開く。
2. 「SafariやChromeで開く」案内が出ることを確認する。
3. 「URLをコピーする」で完全なURLをコピーできることを確認する。
4. 「このまま試す」から、2画面の導入、写真の保存前確認、4匹一覧、大写真確認まで進める。
5. 1匹を選び、完了画面で初めてその日の `ねこだより` と説明されることを確認する。

合格: 一度目のJPEG/PNG選択で進み、外部ブラウザへ移る方法と、そのまま現行オンボを完走する方法の両方が使える。

### B. まっさらなAndroid Chrome

1. reset入口を開く。
2. 「次へ」で `ねこくじ` の説明へ進み、「うちの子の写真を1枚選ぶ」を押す。
3. 写真を選び、まだ保存されていない状態で保存前確認が表示されることを確認する。
4. 「保存して、ねこくじへ」を押し、4匹が表示されることを確認する。
5. 気になる1匹をタップし、大きな写真と「この子を選びますか？」を確認する。
6. 一度4匹へ戻って別の1匹を開き、「この子を選ぶ」で確定する。
7. 完了画面で自分の写真が主役として表示され、選んだ1匹がその日の `ねこだより` になったと初めて説明されることを確認する。
8. `うちのこを見る` と `ねこだよりを見る` の両方から保存結果へ進めることを確認する。
9. 猫の名前や2枚目の写真を求められず、通常タブでAndroid向けのホーム画面追加案内を確認する。

合格: 写真を確定したときだけ正式な `うちのこ` の1枚として保存され、4匹から選んだ1匹だけが `ねこだより` に残る。`QuotaExceededError`、重複保存、成功表示だけの偽陽性がない。

画面上では1匹を選ぶ前に次のよる8時便を約束しない。一方、最初の写真保存後の内部予約は現行仕様であり、公開後は
`docs/instagram-neko-kuji-live-operations-2026-08.md` に従って成立と既存予約の維持を確認する。

### C. iPhone Safari / PWAスポット確認

1. Safariの通常タブで本番入口を開く。
2. 写真選択が一度目から開き、保存前確認と4匹一覧まで進めることを確認する。
3. 4匹が2列で横にはみ出さず、各写真を無理なくタップできることを確認する。
4. 大写真から1匹を選び、完了画面の自分の写真と `ねこだより` を確認する。
5. iPhone向けの共有ボタンと「ホーム画面に追加」案内を確認する。
6. 既存PWAを完全終了して起動し、`うちのこ` または `ねこだより` が開くことを確認する。

合格: SafariとPWAのどちらも操作不能にならず、写真や猫情報が欠けない。

## 2. 変更時に行う回帰確認

次のシナリオは毎日の投稿関門ではない。該当コードを変更したとき、または週次の回帰で行う。

### D. 中断と再訪

導入2画面の途中、写真選択後の保存前確認、4匹一覧、大写真確認、選択後の完了画面で一度閉じ、同じURLから再訪する。端末間引き継ぎも確認する。

合格: 未保存の写真選択を完了済みと誤判定せず、保存後は意味のある直前状態から続く。自分の写真や選んだ `ねこだより` が二重にならず、別の1匹へすり替わらない。

### E. 保存前確認と副作用の境界

写真を選んだあと、保存前確認で一度「写真を選び直す」を使う。別の写真を選び、保存前確認を閉じる、またはページを再読込してから再度進める。

合格: 「保存して、ねこくじへ」を押す前は正式な記録・同期・枚数へ加算されず、押したあとだけ選び直した1枚が一度保存される。

### F. 写真選択のキャンセル・読込失敗

写真選択をキャンセルして再選択する。対応外ファイルでは、再試行できる日本語の案内を確認する。

合格: 白画面や無反応にならず、同じJPEG/PNGを選び直して進める。

### G. 通信切断からの復帰

写真保存または4匹取得中に通信を切り、失敗表示後に通信を戻して再試行する。

合格: 同じ写真で再試行でき、二重登録されない。成功していないのに成功表示を出さない。

### H. 4匹・大写真の読込失敗

通信が不安定な状態で4匹一覧または大写真を開き、失敗表示から再読み込みする。

合格: 「写真をもう一度読み込む」が使え、操作不能にならない。

### I. アカウント作成・ログイン

オンボ完了後、設定からアカウント作成またはログインを行う。キャンセル後に再試行する。

合格: 匿名時の猫、送った写真、届いた写真を失わず、ホームへ戻れる。

### J. 無効なつづきリンク

期限切れ・使用済みの引き継ぎリンクを開く。

合格: 理由が日本語で表示され、復元済みならホームへ、復元できなければやり直しへ進める。

### K. 旧2枚目URL

`/home?from=onboarding_second_photo` と、旧 `next=second_photo` 付きのオンボ完了・アカウント作成URLを開く。

合格: 2枚目の要求やエラーを出さず、現行のホームまたはアカウント作成導線へ静かに正規化される。

## 4. 判定

- AまたはBに未解決の失敗があれば告知を順延する。
- 写真の消失、別人の写真表示、共有範囲の誤り、二重登録、4匹取得・選択結果保存の不成立、操作不能はP0とする。
- CのPWA案内だけが不調でもブラウザ利用が成立する場合はP1だが、iPhoneまたはAndroidの両方で案内が出ない場合は公開前に原因を確認する。
- 軽い表示ずれは証跡を残し、写真保存・4匹取得・選択結果保存・復元が成立する場合だけ次回告知までのP1へ送る。
